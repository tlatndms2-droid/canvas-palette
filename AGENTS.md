# Update and Release boundaries

- Plans contain only user-approved behavior. Do not add adjacent features, shortcuts, alternative workflows, or unrelated verification.
- If extra behavior becomes necessary, stop before implementation and report the reason and added elapsed time.
- Continue resolving ordinary implementation errors, but report when the approved scope, expected elapsed time, or intended Release contents change.
- A Release includes only files changed for the approved task. Preserve unrelated uncommitted user work.
